# I1 — 속성 연관규칙 분석 (근거중심 리포트)

## 0. 개요
- **대상**: 공공데이터포털 999개 데이터셋(교육 400 / 보건 300 / 공공행정 299)의 데이터 지도.
- **트랜잭션 모델**: 각 데이터셋(테이블) = 1 트랜잭션. 아이템 = ① 이산화·롤업된 테이블 속성, ② 보유 컬럼개념(장바구니).
- **알고리즘 파이프라인** (규칙#1 — LLM 추론 배제, 모두 결정적 코드 산출). 아래 §0.1에 단계별 상세.
- 재현 스크립트: `scripts/06_i1_assoc_rules.py`, `scripts/07_i1_synthesis.py`. 원시 규칙표: `analysis/I1_association_rules.md`, `analysis/I1_synthesis.md`.

### 0.1 파이프라인 상세 (6단계)

전체 흐름: **원천 적재 → 수치 이산화 → AOI 롤업 → 트랜잭션 구성 → FP-Growth/연관규칙 → 국소·전체 검증**. 각 단계는 입력·연산·출력이 명시되어 결과를 손으로 재현할 수 있게 설계.

**① 원천 적재 & 형변환**
- `table_map.csv`(테이블 999건), `column_map.csv`(컬럼 9,840건)을 UTF-8로 적재. `table_id` 결측 행 제거.
- 수치 컬럼(`column_cnt·categorical_cnt·numerical_cnt·rec_cnt`, `distinct_cnt·pk_ratio·same_ratio`)을 `to_numeric(errors="coerce")`로 강제 형변환(비수치는 NaN).

**② 1D 클러스터링 = 수치형 이산화** (규칙#2: "수치형은 이산화/클러스터링")
- 대상: `rec_cnt`(레코드수), `column_cnt`(컬럼폭), `numerical_cnt/column_cnt`(수치비).
- 절차: 값이 멱법칙 분포라 **log1p 변환**(`numerical_cnt/column_cnt`는 비율이라 미변환) → **1차원 KMeans**(`n_init=10, random_state=0`, k=rec 5·col 4·수치비 3)로 군집.
- **설명가능성 확보**: 군집중심을 오름차순 정렬해 라벨을 순서대로 매핑(극소<소<중<대<극대 등). 따라서 각 구간은 "원척도 [min~max]"로 환원 가능(§0.2 표). 즉 KMeans가 데이터-구동으로 경계를 정하되, 결과는 사람이 읽는 순서형 구간이 됨.
- 출력 아이템 예: `레코드=중`, `컬럼폭=표준`, `수치비=범주우세`.

**③ AOI 롤업 = 범주 일반화** (규칙#2 AOI, 규칙#3 롤업)
- **출처 일반화**(`table_source` → `기관유형`): 정규식 **접미사/키워드 규칙**으로 7개 개념으로 상향 일반화.
  예) `…교육청|교육지원청|대학교|도서관` → **교육기관**, `…부$|청$|처$|위원회$` → **중앙행정기관**, `…공단|공사|진흥원|재단|병원` → **공공기관/공기업**, `…특별시$|광역시$|도$` → **광역지자체**, `…시$|군$|구$` → **기초지자체**, 문자열 `"소스"` → **미상(placeholder)**.
  → 999개 자유기관명을 7개 개념계층으로 축약(빈발패턴이 통계적으로 의미를 갖도록).
- **컬럼명 정규화**(`col_nm` → `컬럼개념`): 결정적 전처리만 적용 — 괄호내용 제거 `(.*?)`, 공백 제거, 선행 숫자접두(`5_` 등) 제거, 소문자화. **동의어 병합(연번≈순번)은 의도적으로 미적용**(BI 규칙 오염 방지; §6 한계 참조).

**④ 트랜잭션 구성** (테이블 1건 = 1 트랜잭션)
- **(A) 속성 트랜잭션**: 각 테이블에 대해 아이템 집합 = `{cate1=…, cate2=…, 기관=…, 레코드=…, 컬럼폭=…, 수치비=…, 유일키=있음/없음, 상수컬럼=있음/없음}`.
  - `유일키` = 해당 테이블 컬럼 중 `pk_ratio≥0.99`인 컬럼 존재 여부(`column_map` groupby max).
  - `상수컬럼` = `distinct_cnt==1`(정보량 0) 컬럼 존재 여부(groupby min).
- **(B) 컬럼개념 장바구니**: 각 테이블이 **보유한 컬럼개념의 집합**(중복 제거). → "기저귀>맥주"식 동시출현 분석의 입력. 테이블당 평균 9.6개 개념, 전체 고유 개념 4,721종.
- 두 트랜잭션 집합 모두 mlxtend `TransactionEncoder`로 0/1 원-핫 행렬로 변환.

**⑤ FP-Growth 빈발패턴 → 연관규칙** (규칙#2)
- **FP-Growth**(`fpgrowth`)로 최소지지도 이상 빈발 항목집합 추출.
  - 속성(A): `min_support=0.05`(≈50테이블).
  - 컬럼장바구니(B): `min_support≈0.008`(=8테이블), 폭증 방지 위해 `max_len=3`.
- **연관규칙 생성**(`association_rules`, `metric="lift"`)로 각 빈발집합을 선행→후행으로 분해, 5개 지표 계산:
  - **support** = P(선행∧후행), **confidence** = P(후행│선행), **lift** = conf / P(후행)(1이면 독립, >1 양의 연관), **leverage** = P(선행∧후행)−P(선행)P(후행), **conviction** = (1−P(후행))/(1−conf)(∞=완전함의).
- **interestingness 정리**: 선행·후행이 모두 cate1/cate2로만 구성된 **구조적 자명규칙**(cate1↔cate2 계층종속)은 `is_struct`로 식별해 A1(비자명)·A2(자명)로 분리.

**⑥ 국소 채굴 → 전체 검증** (규칙#4: "국소 규칙은 전체에서 검증")
- 컬럼장바구니를 `cate1`(보건/교육/공공행정)별로 분할해 **도메인 내부에서만** FP-Growth+연관규칙 채굴(국소 support·conf·lift).
- 그 후 동일 규칙의 지표를 **전체 999건 원-핫 행렬**에서 재계산(`verify` 함수: `supp/conf/lift` 직접 산출).
- 국소 vs 전체 지표를 나란히 표기 → 국소에서 강했던 규칙이 전체로 일반화되는지(유지) 혹은 무너지는지(약화/비대칭) 판정(§5).

## 1. 핵심 발견 (요약)
1. **[거버넌스 헤드라인]** 출처 결손은 무작위가 아니다 — **'유아및초·중등교육' 데이터셋 100건이 100% 출처 placeholder('소스')**. 특정 수집 배치의 계통적 메타데이터 손실. (lift 6.89, conf 1.00)
2. **[스키마 패밀리]** 최대빈발 컬럼군으로 데이터셋 원형이 드러남 — 사학재정군·의료기관군·POI(위치)군·국가시험군 등. 동일 기관의 동일 템플릿 반복 공개.
3. **["기저귀>맥주" 규칙]** 강한 컬럼 동시출현: `경도→위도`(lift 22.7), `의료기관전화번호→{명,주소}`(46), `연령대→성별`(35), `시도명→시군구명`(39), `교과목코드↔분반`(125).
4. **[규칙#4 실증]** `소재지도로명주소→소재지지번주소`는 공공행정 국소 conf 1.00이나 전체 conf 0.44로 약화 — 국소규칙의 비일반성 포착.

## 2. A. 거버넌스 헤드라인 — 출처 결손의 계통성
연관규칙 A1 최상위가 모두 `유아및초·중등교육`과 `기관=미상(소스)`의 결합(lift 6.9–8.4, conf 1.0)이었음. 분해하면:

| cate2 | placeholder('소스') | 총 | 비율 |
|---|---:|---:|---:|
| **유아및초·중등교육** | **100** | 100 | **100%** |
| 교육일반 | 15 | 100 | 15% |
| 고등교육 | 14 | 100 | 14% |
| 보건의료 | 10 | 300 | 3% |
| 평생·직업교육 | 2 | 100 | 2% |
| 일반행정 | 4 | 299 | 1% |

→ **해석(증거기반)**: 전체 placeholder 145건 중 100건이 이 한 분류. 이 분류는 출처 기관이 일괄 소실된 단일 수집 경로일 가능성. **거버넌스 조치 후보**: 해당 배치의 provenance 복구 우선순위 1순위.
부수적으로 동일 규칙군에서 이 분류는 `유일키=있음`·`상수컬럼=있음`·`컬럼폭=표준`을 함께 동반(conf 0.79–0.84) → 동형 템플릿으로 적재되었음을 시사.

## 5. D. 규칙#4 — 국소 채굴 → 전체 검증
도메인별로 캔 규칙을 전체 999에서 재계산. 대부분 유지되나, **비대칭/약화 사례**가 핵심 교훈:

| 규칙 | 공공행정 국소 conf/lift | 전체 conf/lift | 판정 |
|---|---|---|---|
| 소재지지번주소 → 소재지도로명주소 | 1.00 / 42.7 | 0.92 / 36.6 | **유지** |
| 소재지도로명주소 → 소재지지번주소 | 1.00 / 42.7 | **0.44** / 36.6 | **약화**(역방향 비성립) |
| 경도 → 위도 | 1.00 / 29.9 | 1.00 / 22.7 | 유지(lift는 전체서 하락) |
| 연번 → 주소 | 0.18 / 3.3 | 0.20 / 2.2 | 약함(원래 낮음) |

→ 공공행정 안에서는 도로명·지번이 1:1로 병기되나, **보건 도메인은 지번주소만 단독 보유**하는 케이스가 많아 전체에서 도로명→지번 방향이 깨짐. 국소 강규칙을 전체로 일반화하면 오류가 됨을 실증.

또한 보건 국소에서 `{테이블명·컬럼명·데이터타입·표시형식·컬럼설명}` 동시출현 규칙이 발견됨 → 일부 '보건 데이터셋'은 실데이터가 아니라 **데이터 명세서/사전 파일**임을 시사(거버넌스: 카탈로그 오분류 후보).

## 6. 한계 / 주의
- 컬럼개념은 결정적 정규화(공백·괄호·숫자접두 제거)만 적용. `연번/순번/번호` 같은 **동의어 병합은 미적용**(BI 규칙 오염 방지) — 별도 문자유사도 군집(G3)으로 처리 권장.
- 장바구니 규칙의 support는 낮음(8–44 테이블). lift는 높지만 희소 → 운영 적용 전 도메인 확인 필요.
- table_qty_index·cum_search_num·null_ratio가 전부 0(미충전)이라 활용/품질 축은 분석 불가(G1).
